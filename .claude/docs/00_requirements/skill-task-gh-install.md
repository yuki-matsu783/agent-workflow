# gh/glab CLIインストール 要件定義

## 概要

- **背景**: 他のGitHub/GitLab操作スキル（`task-gh-feature`/`task-gh-issue`/`task-repo-merge-settings`）は `gh`/`glab` CLI が導入・認証済みであることを前提とするが、未導入の環境では都度手動でインストール方法を調べる必要があり、OS・ディストリビューションごとにコマンドが異なるため誤ったインストールをしやすい。
- **目的**: プロジェクトのプラットフォーム（GitHub/GitLab）を自動判定し、対応するCLIをOS・ディストリビューションに応じて決定論的にインストールできるようにする。
- **スコープ**:
  - 含む: プラットフォーム判定、導入確認、ユーザー承認を経たインストール、認証案内
  - 含まない: 認証そのものの自動化（`gh auth login`/`glab auth login` の案内のみ）、CLIが到達できないネットワーク環境での代替手段

---

## ユーザーストーリー

**[As a]** GitHub/GitLab操作スキルを使い始める開発者として、

**[I want]** プロジェクトに応じた `gh`/`glab` CLI を確認なしで誤りなくインストールしたい、

**[So that]** OS・ディストリビューションごとのインストール手順を自分で調べずに、他のGitHub/GitLab操作スキルをすぐ使えるようにするため。

### ユーザーストーリーの別パターン

| パターン | フォーマット | 例 |
|---------|------------|-----|
| 条件付き | Unless | Unless ユーザーがインストールを承認しない場合、スクリプトを実行しない |

---

## 受け入れ基準（Acceptance Criteria）

### メインフロー

- When ユーザーがCLIのインストールを依頼したとき、Shall `git remote get-url origin` からプラットフォームを判定しなければならない
- When プラットフォームが判定できたとき、Shall 対応するCLI（`gh`/`glab`）の導入状態を確認しなければならない
- When CLIが未導入であるとき、Shall インストール前に `AskUserQuestion` でユーザーの承認を得なければならない
- When 承認を得たとき、Shall 同梱スクリプト（`scripts/install_gh.sh`/`scripts/install_glab.sh`）でOS・ディストリビューションに応じて決定論的にインストールしなければならない

### アルタナティブフロー（代替経路）

- When CLIが既に導入済みであるとき、Shall バージョンを表示してインストール処理を行わずに終了しなければならない
- When プラットフォームが判定できないとき、Shall 推測で決め打ちせず `AskUserQuestion` でユーザーに確認しなければならない
- When ヘッドレス実行（`claude -p`、CI等）でユーザー確認ができないとき、Shall インストール確認は自動的に拒否として扱われ、インストールを行わずに停止しなければならない。ヘッドレスで確実にインストールしたい場合は、スキルを介さずインストールスクリプトを直接呼び出す経路を用意しなければならない

### 例外フロー（エラーケース）

- When ユーザーがインストールを拒否したとき、Shall インストールを行わず、公式サイトの手動インストール手順を案内しなければならない
- When インストールに権限エラー（sudo要求等）が発生したとき、Shall その旨をユーザーに伝えなければならない
- When ネットワークエラーが発生したとき、Shall インターネット接続の確認を促さなければならない
- When サポート外プラットフォームであるとき、Shall 公式リリースアーカイブでのインストールを試み、失敗時はエラーメッセージを表示しなければならない

---

## 前提条件

- 対象が git リポジトリであり、プラットフォーム判定に `origin` リモートを使えること（判定不能時はユーザーに確認）
- インストール権限（Linuxは`sudo`、macOSはHomebrewまたは公式インストーラ）があること

---

## 制約条件

- **技術的制約**: プラットフォーム判定は `task-repo-merge-settings`・`task-gh-feature`・`task-gh-issue` と同じ方式に統一する。インストール処理はAIがコマンドを自由に組み立てず、同梱スクリプトに実処理を寄せる
- **ビジネス的制約**: 特になし
- **外部的制約**: ネットワーク経由でのパッケージ取得ができない環境（egressポリシーで外部ホストがブロックされる環境等）では動作しない

---

## 依存関係

- `task-repo-merge-settings`・`task-gh-feature`・`task-gh-issue`: 未導入時の案内先としてこのスキルを参照
- `.claude/rules/claude-config-headless-awareness.md`: ヘッドレス実行時の `AskUserQuestion` 自動拒否の扱い

---

## 非機能要件

| 項目 | 説明 |
|------|------|
| 決定論性 | 同一OS・ディストリビューションであれば常に同じ手順でインストールされること（AIの都度の判断に依存しない） |
| 安全性 | ユーザー承認を得ずにインストールを実行しないこと |
