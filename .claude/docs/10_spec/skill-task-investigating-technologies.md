# 技術調査レポート作成 仕様書

## 概要

- **背景・目的**: `.claude/docs/00_requirements/skill-task-investigating-technologies.md` を参照。
- **スコープ**: `task-investigating-technologies` スキルの照合・ヒアリング・保存の入出力と処理フローを定義する。

---

## 入力（Input）定義

### 入力元

- **入力元**: ユーザーへのヒアリング（調査対象・評価基準・メリデメ・代替案・コスト等）

### 入力データ

| 項目名 | 型 | 必須 | 説明 | デフォルト値 |
|--------|----|------|------|-------------|
| タイトル・調査対象 | string | Y | 技術・ライブラリ名 | - |
| 評価基準 | string[] | Y | 機能性/パフォーマンス/メンテナ性/コミュニティ/学習コスト/導入コスト/ライセンス等から選択 | `references/conventions.md` の一般的評価軸 |
| メリット/デメリット | string[] | Y | それぞれ3つ以上、根拠付き | - |
| 代替案比較 | table | N | 評価軸ごとの比較表 | 空欄可 |
| 結論 | enum(採用/保留/不採用) | Y | 3択のいずれか | - |

### 入力フォーマット

対話ヒアリングによる自然言語入力。

---

## 出力（Output）定義

### 出力先

- **出力先**: リポジトリ内のMarkdownファイル（例: `investigation/<対象>.md`、`tech/<対象>.md`）

### 出力データ

| 項目名 | 型 | 説明 | デフォルト値 |
|--------|----|------|-------------|
| 技術調査レポート | Markdown | テンプレート骨格を保持したファイル | `assets/tech-investigation.template.md` |

### ステータス（スキルの終了状態）

| 状態 | 意味 |
|------|------|
| 新規作成完了 | ファイルパスと結論（採用/保留/不採用）を報告 |
| 既存更新 | 類似レポートを更新して報告 |

---

## 処理フロー

### 基本フロー

1. `find` + `grep` で既存の調査レポートとの類似度を確認する
2. 類似が無ければ `assets/tech-investigation.template.md` を読み込み、新規ファイルにコピーする
3. 概要（タイトル・日付・調査者・目的・対象）をヒアリングして記入する
4. 調査の背景と動機（契機・課題・期待効果）を記入する
5. 評価基準を `references/conventions.md` を参照しつつ決定する
6. 調査対象の詳細（公式サイト・バージョン・ライセンス・主な機能・初見の印象）を記入する
7. メリット・デメリットをそれぞれ3つ以上、根拠付きで記入する
8. 代替案との比較表を作成する
9. コスト評価（導入・学習・運用・移行）を記入する
10. 結論（採用/保留/不採用）と次回アクションを記入する
11. 完成したレポートをユーザーに提示し、承認を得てから保存する
12. ファイルパスと結論を報告する

### 代替フロー

1. 既存レポートに類似するものが見つかった場合、更新か新規作成かをユーザーに確認する

### 例外フロー

1. 結論が即座に出せない → 「保留」とし、PoC実施等の追加検証を推奨する
2. 調査対象が不明確 → 技術名・公式サイト・ドキュメントURLをユーザーに確認する
3. 評価基準が不明 → `references/conventions.md` から一般的な評価基準を確認する

---

## データ設計

### 一般的な評価軸

| 評価軸 | 説明 |
|--------|------|
| 機能性 | 求められる機能を満たしているか |
| パフォーマンス | 処理速度、スループット、レイテンシ |
| メンテナ性 | コードの保守性、テストのしやすさ |
| コミュニティ/エコシステム | ドキュメントの充実度、コミュニティの活発さ |
| 学習コスト | 習得に必要な時間と難易度 |
| 導入コスト | 既存システムへの統合・移行コスト |
| ライセンス | ライセンスの種類とビジネスへの影響 |
