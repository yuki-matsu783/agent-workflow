# 仕様書作成 仕様書

## 概要

- **背景・目的**: `.claude/docs/00_requirements/skill-task-spec.md` を参照。
- **スコープ**: `task-spec` スキルの照合・ヒアリング・保存の入出力と処理フローを定義する。

---

## 入力（Input）定義

### 入力元

- **入力元**: ユーザーへのヒアリング（タイトル・背景・目的・スコープ・入出力・処理フロー等）、または対応する要件定義書

### 入力データ

| 項目名 | 型 | 必須 | 説明 | デフォルト値 |
|--------|----|------|------|-------------|
| タイトル | string | Y | 仕様の名前 | - |
| 入力定義 | table | Y | 入力元・項目名・型・必須/任意・フォーマット | - |
| 出力定義 | table | Y | 出力先・項目名・型・フォーマット・ステータスコード | - |
| 処理フロー | string | Y | 基本フロー必須、代替・例外フローは任意 | - |
| データ設計/インターフェース/エラーハンドリング | string | N | 該当する場合に記入 | 空欄 |

### 入力フォーマット

対話ヒアリングによる自然言語入力。構造化フォーマットは扱わない。

---

## 出力（Output）定義

### 出力先

- **出力先**: リポジトリ内のMarkdownファイル（例: `.claude/docs/10_spec/<title>.md`）

### 出力データ

| 項目名 | 型 | 説明 | デフォルト値 |
|--------|----|------|-------------|
| 仕様書 | Markdown | テンプレート骨格を保持したファイル | `assets/spec.template.md` |

### ステータス（スキルの終了状態）

| 状態 | 意味 |
|------|------|
| 新規作成完了 | ファイルパスと概要を報告 |
| 既存更新 | 類似ドキュメントを更新して報告 |
| 中断（未承認） | ユーザー承認前は保存しない |

---

## 処理フロー

### 基本フロー

1. `find` + `grep` で既存の仕様ドキュメントとの類似度を確認する
2. 類似が無ければ `assets/spec.template.md` を読み込み、新規ファイルにコピーする
3. 概要（タイトル・背景・目的・スコープ）をヒアリングして記入する
4. 入力定義（入力元・項目・フォーマット）をヒアリングして記入する
5. 出力定義（出力先・項目・フォーマット・ステータスコード）をヒアリングして記入する
6. 処理フロー（基本→代替→例外の順）をヒアリングして記入する
7. データ設計・インターフェース定義・エラーハンドリングを必要に応じて記入する
8. 前提条件・制約条件・非機能要件を必要に応じて記入する（不要なら空欄のまま残す）
9. 完成した仕様書をユーザーに提示し、承認を得てから保存する
10. ファイルパスと概要を報告する

### 代替フロー

1. 既存ドキュメントに類似するものが見つかった場合、更新か新規作成かをユーザーに確認する
2. 更新を選んだ場合は該当ドキュメントを読み込み、ユーザーの指示に従って編集する

### 例外フロー

1. 該当する要件定義書が存在しない → 作成対象の仕様が明確化できる情報をユーザーから直接ヒアリングする

---

## データ設計

### 骨格見出し（テンプレートの構成）

概要 → 入力定義 → 出力定義 → 処理フロー → データ設計 → インターフェース定義 → エラーハンドリング → 前提条件 → 制約条件 → 非機能要件 → テストシナリオ → 関連するドキュメント → レビュー記録

## エラーハンドリング

### エラーコード一覧

| 状況 | 対処 |
|------|------|
| 既存ドキュメントとの類似あり | 更新/新規作成をユーザーに確認 |
| 対応する要件定義書が無い | ユーザーから直接ヒアリングして進める |
| 未承認 | 保存せず、修正点を反映してから再提示 |
