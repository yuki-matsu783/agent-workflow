# スキル体系 仕様書

## 概要

- **背景・目的**: `.claude/docs/00_requirements/スキル体系.md` を参照。
- **スコープ**:
  - 含む: 3層（workflow/work/task）の定義・命名規則・承認方式、既存スキルのリネーム対応表、`work-ticket-driven` における用語対応、ワーク完了チェックポイントの位置と入出力、`workflow-guard.sh` の `git mv` 許可拡張の仕様
  - 含まない: 敵対的レビューエージェントの自動起動ロジックの実装仕様（次段階）

---

## 3層の定義

| 層 | 命名 prefix | 実現単位 | チェックポイント | 承認者 |
|---|---|---|---|---|
| ワークフロー | `workflow-*` | ワーク（`work-*`）の組み合わせ | ワーク間に必ず設置 | 人間（MRレビュー または `AskUserQuestion`） |
| ワーク | `work-*` | タスク（`task-*` 相当の実行単位、チケット駆動ワークフローではチケット）の組み合わせ | 複数タスク完了時点に設置 | 敵対的レビューエージェント（本仕様では位置と入出力のみ定義。自動起動の実装は対象外） |
| タスク | `task-*` | 作業レベルの手順 | チェックポイントなし | 実行者自身によるセルフレビュー |

判定基準（要件定義書のAcceptance Criteriaと同一）:

1. ワーク間に人間承認が必須のスキル → `workflow-*`
2. タスク相当の組み合わせで、ワーク内は人間承認不要、完了時に敵対的レビューが入るスキル → `work-*`
3. セルフレビューで完結する作業レベルのスキル → `task-*`

`.claude/hooks/workflow-types.json` の `types`（`investigation` / `implementation` / `retrospective` / `ai-asset-design` / `ai-asset-implementation`）は**チケットの作業タイプ名**であり、本仕様の「タスク」とは別の識別子体系。`work-ticket-driven` におけるチケットは3層構造の「タスク」に相当するが、フック実装との整合を優先し、JSON のキー名・チケットの呼称（「チケット」）は変更しない。

## ワーク完了チェックポイント

`work-*` スキルは、配下の全タスク（チケット駆動ワークフローでは全チケット）が完了した時点で、報告の前に以下のチェックポイントを設置する。

| 項目 | 内容 |
|------|------|
| 位置 | 全タスク完了直後、結果報告の作成前 |
| レビュー対象 | ワーク開始コミット（最初のタスク着手時のコミット）から現在までの全差分 |
| 出力 | 承認 / 差し戻し（差し戻し時は追加タスクで対応する） |
| 承認者 | 敵対的レビューエージェント（自動起動の実装は本仕様のスコープ外） |
| 現状の運用 | 自動化されるまでは、結果報告に「レビュー結果: 未実施（今後の自動化対象）」と明記する |

`work-ticket-driven` の場合、既存の `retrospective` チケット（セルフレビュー・結果報告の作成、タスク層の役割）は本チェックポイントと**別物**として維持する。retrospective は「実行者自身の振り返り」、ワーク完了チェックポイントは「第三者（敵対的レビューエージェント）による承認」であり、両者を統合しない。

## `workflow-guard.sh` の `git mv` 許可拡張

### 背景

`.claude/hooks/workflow-guard.sh` の `wf_validate_mv()` は、`mv` / `git mv` の対象パスを `wip/10_tickets/**` 配下のみに限定している。スキルのリネーム作業（`.claude/skills/**` の `git mv`）はこの制約でブロックされる（WF003）。

### 仕様

`ai-asset-implementation` type の doing チケットが存在する間に限り、`.claude/skills/**` 配下の `mv` / `git mv` を許可する。

```bash
wf_validate_mv() {
    local tok
    for tok in "$@"; do
        case "${tok}" in
            -*) continue ;;
            QUOTED) return 1 ;;
        esac
        case "${tok//\\//}" in
            wip/10_tickets/*) continue ;;
            .claude/skills/*)
                [ "${TICKET_TYPE}" = "ai-asset-implementation" ] && continue
                return 1
                ;;
            *) return 1 ;;
        esac
    done
    return 0
}
```

- `TICKET_TYPE` は既存のグローバル変数（doing チケットの frontmatter `type` から `workflow-lib.sh` の `wf_init` がセットする）をそのまま使う。追加の状態管理は不要。
- Edit/Write ツールでの `.claude/skills/**` への書き込み許可は、`ai-asset-implementation` type の `allow_paths` に既に含まれているため変更不要（パス判定 `wf_resolve` は Bash の `git mv` 判定とは独立した経路）。
- この拡張により、`ai-asset-implementation` 以外の type（investigation・implementation・retrospective・ai-asset-design）では従来どおり `.claude/skills/**` の `git mv` はブロックされる。
