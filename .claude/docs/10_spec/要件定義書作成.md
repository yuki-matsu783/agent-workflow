# 要件定義書作成 仕様書

## 概要

- **背景・目的**: `.claude/docs/00_requirements/要件定義書作成.md` を参照。
- **スコープ**: `task-requirements` スキルの照合・ヒアリング・保存の入出力と処理フローを定義する。

---

## 入力（Input）定義

### 入力元

- **入力元**: ユーザーへのヒアリング（タイトル・背景・目的・スコープ・ロール・やりたいこと・理由・受け入れ基準）

### 入力データ

| 項目名 | 型 | 必須 | 説明 | デフォルト値 |
|--------|----|------|------|-------------|
| タイトル | string | Y | 要件の名前 | - |
| ユーザーストーリー | As a/I want/So that | Y | EARS標準形。他パターンも可 | 標準形 |
| 受け入れ基準 | When/Shall | Y | メインフロー必須、代替・例外フローは任意 | - |
| 前提/制約/依存/非機能 | string | N | 不要なら空欄のまま | 空欄 |

### 入力フォーマット

対話ヒアリングによる自然言語入力。構造化フォーマットは扱わない。

---

## 出力（Output）定義

### 出力先

- **出力先**: リポジトリ内のMarkdownファイル（例: `.claude/docs/00_requirements/<title>.md`）

### 出力データ

| 項目名 | 型 | 説明 | デフォルト値 |
|--------|----|------|-------------|
| 要件定義書 | Markdown | テンプレート骨格を保持したファイル | `assets/requirements.template.md` |

### ステータス（スキルの終了状態）

| 状態 | 意味 |
|------|------|
| 新規作成完了 | ファイルパスと概要を報告 |
| 既存更新 | 類似ドキュメントを更新して報告 |
| 中断（未承認） | ユーザー承認前は保存しない |

---

## 処理フロー

### 基本フロー

1. `find` + `grep` で既存の要件ドキュメントとの類似度を確認する
2. 類似が無ければ `assets/requirements.template.md` を読み込み、新規ファイルにコピーする
3. 概要（タイトル・背景・目的・スコープ）をヒアリングして記入する
4. ユーザーストーリー（EARS標準形。必要に応じて他パターン）をヒアリングして記入する
5. 受け入れ基準（メインフロー→アルタナティブフロー→例外フローの順、EARS When/Shall）をヒアリングして記入する
6. 前提条件・制約条件・依存関係・非機能要件を必要に応じて記入する（不要なら空欄のまま残す）
7. 完成した要件定義書をユーザーに提示し、承認を得てから保存する
8. ファイルパスと概要を報告する

### 代替フロー

1. 既存ドキュメントに類似するものが見つかった場合、更新か新規作成かをユーザーに確認する
2. 更新を選んだ場合は該当ドキュメントを読み込み、ユーザーの指示に従って編集する

### 例外フロー

1. ユーザーがユーザーストーリー・受け入れ基準のパターンを明示しない → EARSバリエーション早見表から提案する

## データ設計

### EARSフォーマットのバリエーション早見表

| 種別 | フォーマット | 使用場面 |
|------|------------|---------|
| 標準ユーザーストーリー | As a / I want / So that | 機能要件の記述 |
| 理由強調型 | Now that / In order that | 前提条件が重要な場合 |
| 条件付ユーザーストーリー | Unless | 制約や条件を強調する場合 |
| 肯定型 AC | When / Shall | 正常系・実行系の要件 |
| 否定型 AC | When / Shall not | 禁止・制約系の要件 |
| 条件付 AC | If / Then | 分岐・条件処理の要件 |
| 状態遷移型 AC | When / Shall transition to | ステータス遷移を明確にする場合 |
