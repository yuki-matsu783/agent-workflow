# 軽作業ワークフロー 仕様書

## 概要

- **背景・目的**: `.claude/docs/00_requirements/軽作業ワークフロー.md` を参照。
- **スコープ**: `workflow-quick-request` スキルの判定・状態確認・宣言・実施・報告・振り返りの入出力と処理フローを定義する。振り分け自体を強制するフックの仕様は `.claude/docs/10_spec/ワークフロー振り分け実施済み判定.md`（`workflow-issue-mr-driven` と共有するメタ文書）を参照。

---

## 入力（Input）定義

### 入力元

- **入力元**: ユーザーの依頼、`git`/`gh` コマンドの出力（状態確認）

### 入力データ

| 項目名 | 型 | 必須 | 説明 | デフォルト値 |
|--------|----|------|------|-------------|
| 依頼内容 | string | Y | 判定基準表に照らす対象 | - |
| 未コミット変更の扱い | enum | 条件付き | コミット/stash/破棄/中断のいずれか | - |
| 作業範囲宣言 | string | Y | やること・触るファイル・やらないこと | - |

### 入力フォーマット

対話ヒアリングとコマンド出力。構造化フォーマットは扱わない。

---

## 出力（Output）定義

### 出力先

- **出力先**: ユーザーへの報告、対象ファイルの変更（ある場合）

### 出力データ

| 項目名 | 型 | 説明 | デフォルト値 |
|--------|----|------|-------------|
| 判定結果 | string | 1行の判定理由 | - |
| 作業範囲宣言 | string | 2〜4行 | - |
| 完了報告 | string | 変更ファイル・確認内容・積み残し | - |
| 振り返り合意 | enum | 軽微修正/issue化/切替/不要のいずれか | - |

### ステータス（スキルの終了状態）

| 状態 | 意味 |
|------|------|
| 完了（軽作業） | 報告・振り返りまで完了 |
| 切り替え | `workflow-issue-mr-driven` へ移行 |
| 中断 | ユーザーの選択により停止 |

## 処理フロー

### 承認ポイント

| # | タイミング | 確認内容 |
|---|-----------|---------|
| ① | 手順0 | 軽作業かどうかの境界判定（迷う場合） |
| ② | 手順1 | 未コミット変更・非デフォルトブランチの扱い |
| ③ | 手順3 | 範囲逸脱時の続行方針 |
| ④ | 手順5-3 | 振り返り候補への合意 |

### 基本フロー

1. 依頼を判定基準表（成果物・振る舞い・規模・検証・追跡・ユーザーの指定）に当てはめ、1行で判定を述べる
2. ファイル変更を伴う場合、状態確認（`git branch --show-current`、`git status --short`、デフォルトブランチ確認）を行う
3. やること・触るファイル・やらないことを2〜4行で宣言する
4. 宣言した範囲内で実施する（範囲を超えたら止まる）
5. 変更したファイルと要点、確認した内容、積み残しを報告する
6. 使ったAIアセット（スキル・フック・ルール・エージェント）を棚卸しし、気付き（足りなかった/邪魔だった/無かった/問題なし）を1行ずつ挙げる
7. 候補を「軽微」「振る舞いが変わる」の2つの重さに分け、`AskUserQuestion` でユーザーに合意を得る

### 代替フロー

1. 判定がissue-pr側に該当 → `workflow-issue-mr-driven` を読み込んで切り替える
2. 境界上で判断できない → `AskUserQuestion` で確認する
3. 未コミットの変更がある → コミット/stash/破棄/中断をユーザーに確認する（自動判断しない）

### 例外フロー

1. `wip/10_tickets/10_doing/` にチケットがある → 軽作業を割り込ませず、`work-ticket-driven` の再開が正しいか確認する
2. 現在ブランチがデフォルトブランチと異なる → 対話実行なら `AskUserQuestion` で確認、ヘッドレス実行なら確認せず現在のブランチのまま進める
3. 作業中に範囲を超えた → 止めて範囲拡大/切替/中断を確認する
4. 振り返りで「軽微」が振る舞いの変更に及んだ → 止めて新規issueを作り `workflow-issue-mr-driven` で進めることを合意し直す

## データ設計

### 軽作業判定表

| 観点 | 軽作業（このスキル） | workflow-issue-mr-driven |
|------|---------------------|--------------------------|
| 成果物 | 回答・説明・調査結果のみ（ファイル変更なし） | コードや設定の変更を伴う開発作業 |
| 振る舞い | 変わらない（typo、コメント、ドキュメント、フォーマット、設定値の微調整） | 変わる（機能追加、バグ修正、リファクタリング、依存の追加・更新） |
| 規模 | 1〜3ファイル、同一ディレクトリ内に閉じる | 複数モジュールにまたがる、または4ファイル以上 |
| 検証 | 目視・既存テストの実行で足りる | テストの追加・変更やレビューが必要 |
| 追跡 | 経緯をGitHubに残す必要がない | issue/PRで経緯を追いたい、他の人がレビューする |
| ユーザーの指定 | 「軽く」「issue不要」「質問」など | 「issue駆動で」「PRにして」「#Nをやって」など |

### 振り返り候補の重さの区分

| 重さ | 該当するもの | 合意の形 |
|------|-------------|---------|
| 軽微 | SKILL.md・ルール・テンプレートの文言修正など、振る舞いが変わらないもの | 「このまま軽作業として続けて修正する」 |
| 振る舞いが変わる | フックのロジック変更、スキルの手順変更、フック・スキル・ルール・エージェントの新規作成、settings.jsonの変更 | 「新規issueを作って `workflow-issue-mr-driven` で進める」 |

## インターフェース定義

### 既存スキルへの委譲内容

| 呼び出し元/連携先 | 用途 |
|-----------|------|
| `workflow-issue-mr-driven` | 判定がissue-pr側に該当する場合の切り替え先 |
| `task-gh-issue` | 振り返りから「issueとして記録だけする」場合の作成モード |

## エラーハンドリング

### エラーコード一覧

| 状況 | 対処 |
|------|------|
| `[WF101]` でブロック | このスキルまたは`workflow-issue-mr-driven`を読み込んでからやり直す |
| `wip/10_tickets/10_doing/` にチケットがある | チケット駆動ワークフロー中。軽作業を差し込まず状況を報告 |
| 作業中に範囲超過 | 止めて確認する |
| 判定がissue-pr側だった | `workflow-issue-mr-driven` に切り替え、このスキルの手順1以降に進まない |
| 変更が既存テストを壊した | 範囲内なら直す、範囲を超えるなら止めて確認する |
