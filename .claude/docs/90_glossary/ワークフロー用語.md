# ワークフロー用語

`workflow-issue-mr-driven` / `work-ticket-driven` などで使われる主要な用語の一覧。

### 作業の振り分け

依頼内容を問わず、着手前に `workflow-issue-mr-driven` か `workflow-quick-request` のいずれかをSkillツールで読み込んで宣言すること。フック（`workflow-entry.sh`）がWF101で強制する。

- 定義元: `CLAUDE.md`「作業の振り分け（必須）」、`.claude/docs/10_spec/ワークフロー振り分け実施済み判定.md`

### チケット

`work-ticket-driven` における作業単位。`wip/10_tickets/00_todo/` → `10_doing/` → `20_done/` と移動しながら1枚ずつ実施する。3層構造では「タスク」に相当する。

- 定義元: `.claude/skills/work-ticket-driven/SKILL.md`、`.claude/docs/10_spec/スキル体系.md`

### DoD（完了条件）

チケットに書く「何を満たせば完了か」のチェックリスト。実装チケットの検証基準、振り返りチケットの確認項目のもとになる。

- 定義元: `.claude/skills/work-ticket-driven/assets/ticket.template.md`

### allowed_paths

チケットのfrontmatterに書く、type定義外で確認なしに触りたいパスの追加指定。global の deny を貫通したり ask を省略したりはできない。

- 定義元: `.claude/hooks/workflow-types.json`、`.claude/skills/work-ticket-driven/SKILL.md`

### draft PR

`workflow-issue-mr-driven` の手順4で、featureブランチ作成後にissueへ `Closes #N` を含む本文で作成するdraft状態のPull Request。全チケット完了後、承認③を経てready for reviewにする。

- 定義元: `.claude/skills/workflow-issue-mr-driven/SKILL.md`

### 承認①②③

`workflow-issue-mr-driven` における人間の承認ポイント。①どのissueで対応するか、②issue本文案・ブランチ名・PRタイトル、③draft PRをready for reviewにするか、の3箇所。

- 定義元: `.claude/skills/workflow-issue-mr-driven/SKILL.md`

### ワーク完了チェックポイント

`work-*` スキル配下の全チケットが完了した時点で、結果報告の前に設置するチェックポイント。承認者は敵対的レビューエージェント（自動起動の実装は今後の課題。現状は「レビュー結果: 未実施」と明記して運用）。

- 定義元: `.claude/docs/10_spec/スキル体系.md`

### WFコード（例: WF101, WF003）

フック（`workflow-entry.sh` / `workflow-guard.sh`）がブロック・確認要求を出す際のエラーコード。対処法は各コードのメッセージに含まれる。

- 定義元: `.claude/docs/10_spec/ワークフロー振り分け実施済み判定.md`、`.claude/docs/10_spec/チケット駆動ワークフロー.md`
