# ワークフロー用語

`workflow-issue-mr-driven` / `work-ticket-driven` などで使われる主要な用語の一覧。

### 作業の振り分け

依頼内容を問わず、着手前に `workflow-issue-mr-driven` か `workflow-quick-request` のいずれかをSkillツールで読み込んで宣言すること。フック（`workflow-entry.sh`）がWF101で強制する。

- 定義元: `CLAUDE.md`「作業の振り分け（必須）」、`.claude/docs/10_spec/ワークフロー振り分け実施済み判定.md`

### AIアセット

`skill` / `rule` / `hook` / `agent` の総称。作成・修正は `task-ai-asset-creator` が担い、チケット type の `ai-asset-design`（要件・仕様書のみ変更）/ `ai-asset-implementation`（フック・ルール・スキル・`settings.json` を変更）が対応する作業範囲を分ける。

- 定義元: `.claude/skills/task-ai-asset-creator/SKILL.md`、`.claude/docs/90_glossary/チケットtype.md`

### チケット

`work-ticket-driven` における作業単位。`wip/10_tickets/00_todo/` → `10_doing/` → `20_done/` と移動しながら1枚ずつ実施する。3層構造では「タスク」に相当する。

- 定義元: `.claude/skills/work-ticket-driven/SKILL.md`、`.claude/docs/10_spec/スキル体系.md`

### DoD（完了条件）

チケットに書く「何を満たせば完了か」のチェックリスト。実装チケットの検証基準、振り返りチケットの確認項目のもとになる。

- 定義元: `.claude/skills/work-ticket-driven/assets/ticket.template.md`

### allowed_paths

チケットのfrontmatterに書く、type定義外で確認なしに触りたいパスの追加指定。global の deny を貫通したり ask を省略したりはできない。

- 定義元: `.claude/hooks/workflow-types.json`、`.claude/skills/work-ticket-driven/SKILL.md`

### draft PR

`workflow-issue-mr-driven` の手順4で、featureブランチ作成後にissueへ `Closes #N` を含む本文で作成するdraft状態のPull Request。全チケット完了後、承認③を経てマージ前作業を行い、`merge-prep.sh ready` でready for reviewにする（`gh pr ready` の直接実行はWF015で拒否される）。マージは人間が行う。

- 定義元: `.claude/skills/workflow-issue-mr-driven/SKILL.md`

### 承認①〜⑥

`workflow-issue-mr-driven` における人間の承認ポイント。①どのissueで対応するか、②issue本文案・ブランチ名・PRタイトル、③マージ前作業（wipリセット → コンフリクト確認 → issueコメント → draft解除）に進むか、④各ワーク完了時のPRレビュー（`AskUserQuestion` で待たず応答を終える）、⑤default ブランチとの衝突を解消してよいか、⑥issueコメントの本文そのもの、の6箇所。

- 定義元: `.claude/skills/workflow-issue-mr-driven/SKILL.md`、`.claude/docs/10_spec/skill-workflow-issue-mr-driven.md`

### ワーク完了チェックポイント

`work-*` スキルで1つのワーク（同じチケットtypeのチケット群）が完了した時点で、次のワークの着手前に設置するチェックポイント。`work-ticket-driven` の現行運用では承認者は人間（`workflow-issue-mr-driven` 経由ならPRレビュー、単独なら `AskUserQuestion`）。境界の判定とレビュー状態の遷移は `work-boundary.sh` が行い、状態は `wip/10_tickets/review-state.json` に残る。

- 定義元: `.claude/docs/10_spec/スキル体系.md`、`.claude/docs/10_spec/skill-work-ticket-driven.md`「ワーク境界の判定とレビュー状態」

### マージ前作業

全ワーク完了・最後のワークのレビュー完了後、draft PRを解除する前に行う作業。wipの成果物のリセット（`reset-wip`）→ default ブランチとのコンフリクト確認（`check-conflicts`）→ 関連issue（`Closes #N`）へのコメント（`notify-issue`）→ draft解除（`ready`）の順に `merge-prep.sh` が実行・記録し、`ready` は先行ステップの記録と再検証を通ったときだけ `gh pr ready` を実行する。

- 定義元: `.claude/docs/10_spec/skill-work-ticket-driven.md`「マージ前作業の判定と状態」、`.claude/docs/10_spec/skill-workflow-issue-mr-driven.md`「完了処理」

### merge-prep.json

`wip/merge-prep.json`。マージ前作業の状態（`reset` / `checked` / `notified` / `ready`）と証跡（削除一覧・衝突判定のSHA・コメントURL）を持つ。`merge-prep.sh` だけが書き、直接の書き換えはWF012で拒否される。PR番号が現在ブランチのPRと一致しなければ失効。wipリセットでは削除されない。`wip/10_tickets/review-state.json` も同じくWF012で直接の書き換えが拒否される対象。

**WF012の例外（issue #51）**: `git` が実際にマージ進行中（`MERGE_HEAD` が存在する）**かつ**対象ファイル自身がunmerged状態（`git diff --name-only --diff-filter=U` に含まれる）の両方を満たすときに限り、この2ファイルへの直接書き換えが許可される（コンフリクト解消のため）。編集後はPostToolUseで内容（有効なJSON・マーカー残存なし・unmerged解消済み）が警告付きで検証される。両条件を満たさない場合は現行どおり常時拒否される。

- 定義元: `.claude/docs/10_spec/skill-work-ticket-driven.md`「入力データ（マージ前作業の状態）」、同「マージコンフリクト解消中の直接編集（issue #51）」

### WFコード（例: WF101, WF003）

フック（`workflow-entry.sh` / `workflow-guard.sh` / `workflow-boundary.sh`）およびスクリプト（`work-boundary.sh` / `merge-prep.sh`）がブロック・確認要求・前提未充足を出す際のエラーコード。対処法は各コードのメッセージに含まれる。WF011〜WF016はワーク境界・マージ前作業に関するもの（WF015 = `gh pr ready` の直接実行、WF016 = `merge-prep.sh` の前提未充足）。

- 定義元: `.claude/docs/10_spec/ワークフロー振り分け実施済み判定.md`、`.claude/docs/10_spec/skill-work-ticket-driven.md`
