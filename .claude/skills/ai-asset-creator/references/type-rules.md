# アセット種類判定規約

ユーザーの要望を skill / rule / hook のいずれに分類するかの判定規約です。

## 種類一覧

### skill

Claude Code が特定のユーザーの指示に応じて自動的に発火し、ワークフローを実行するアセット。

**判定基準:**
- ユーザーが具体的なタスクを「作って」「作成して」と依頼している
- 複数のステップからなるワークフローを含む
- `description` にトリガーとなるユーザーの言葉を記載する
- `SKILL.md` に手順が記述される

**例:**
- "issue 作成するスキルを作って"
- "テストを実行するスキル"
- "ドキュメントを生成する指示"

### rule

継続的に適用されるルール・制約・規約。

**判定基準:**
- 特定の条件下で常に適用されるべき事項
- 違反検知や制約の定義が目的
- プロジェクト全体にわたって適用される
- `.claude/rules/` 以下に配置される

**例:**
- "コーディング規約を定義して"
- "コードレビューのチェックリスト"
- "セキュリティの制約ルール"

### hook

特定のイベント発火時に自動的に実行されるスクリプト。

**判定基準:**
- 特定のイベント（PreToolUse, PostToolUse, Stop など）に紐づく
- bash や sh で実装される
- `settings.json` の `hooks` セクションに登録される
- `.claude/hooks/` 以下に配置される

**例:**
- "Bash 実行前にファイルの権限をチェックする"
- "コミット前に lint を実行する"
- "ツール使用前に環境変数を検証する"

## 曖昧な場合の判定フロー

```
ユーザーの要望を受け取る
    │
    ├─ イベント発火 + スクリプト実行か？
    │   ├─ はい → hook
    │   └─ いいえ → 次へ
    │
    ├─ 継続的・宣言的な制約・規約か？
    │   ├─ はい → rule
    │   └─ いいえ → 次へ
    │
    └─ タスク自動化のワークフローか？
        ├─ はい → skill
        └─ わからない → ユーザーに確認
```

## 名前付け規則

| 種類 | ファイル名の例 | ディレクトリ |
|------|---------------|-------------|
| skill | `<name>/SKILL.md` | `.claude/skills/<name>/` |
| rule | `<name>.md` | `.claude/rules/` |
| hook | `<name>.sh` | `.claude/hooks/` |
