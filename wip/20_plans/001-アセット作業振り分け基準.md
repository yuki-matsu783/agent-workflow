# .claude 配下アセット作業の振り分け基準

- 作成元チケット: 001-ai-asset-design-アセット作業振り分け基準.md
- 作成日: 2026-08-30

## 調査サマリ

- `workflow-quick-request/SKILL.md` 手順 0 の判定表は「成果物・振る舞い・規模・検証・追跡・ユーザーの指定」の 6 観点で切り分けており、`.claude/` 配下のアセット（スキル・フック・ルール・エージェント・settings.json）の作成・変更について直接の記述が無い
- 同スキル手順 5-3（振り返り候補の重さの区分）では「フック・スキル・ルール・エージェントの新規作成、settings.json の変更」を既に「振る舞いが変わる」＝ issue-pr 側と分類済みだが、手順 0 の判定表には反映されていない
- `.claude/docs/10_spec/軽作業ワークフロー.md` は SKILL.md 手順 0 / 5-3 と 1:1 対応する仕様書で、`### 軽作業判定表` と `### 振り返り候補の重さの区分` に同じ内容がある。SKILL.md を変更する場合はこの仕様書も揃える
- `.claude/docs/10_spec/ワークフロー振り分け実施済み判定.md`（issue #4 が「入口ガード仕様書」と呼ぶ文書）には判断基準（判定表の中身）の記述が無い。フック WF101 の入出力・状態遷移だけを扱う横断メタ文書で、スコープ外に「振り分けスキルの中身（各 SKILL.md）」を明記している（`grep` で「判断基準」「判定表」いずれも該当なしを確認済み）。→ 同期対象外
- `.claude/docs/00_requirements/軽作業ワークフロー.md` は判定基準表を「成果物・振る舞い・規模・検証・追跡・ユーザーの指定」と汎用的に参照するのみで、行を列挙していない。→ 行追加は不要
- `CLAUDE.md`「作業の振り分け」セクションは表 1 つ（workflow-issue-mr-driven / workflow-quick-request の使い分け）と、その下に箇条書きで補足ルールを並べる構成。`.claude/` 配下アセット作業の入口は、この既存の箇条書き群に 1 行追加する形が既存構造と整合する

## 変更方針

判定表・重さ区分・CLAUDE.md の 3 箇所に、同じ基準を異なる形式（表の行 / 箇条書き）で反映する。

1. **`workflow-quick-request/SKILL.md` 手順 0 の判定表**に観点「対象」の行を追加する
2. **`.claude/docs/10_spec/軽作業ワークフロー.md` の `### 軽作業判定表`**に SKILL.md と同一の行を追加する（1:1 対応を維持）
3. **`CLAUDE.md`「作業の振り分け」**の既存箇条書きの末尾に、`.claude/` 配下アセット作業の入口を 1 行追加する

`### 振り返り候補の重さの区分` は既に「フック・スキル・ルール・エージェントの新規作成、settings.json の変更」＝振る舞いが変わる、と一致しているため変更しない（追加する判定表の行の「例外」条件をこの区分に合わせる）。

### 確定した文言

**判定表の追加行**（SKILL.md・仕様書で共通）:

| 観点 | 軽作業（このスキル） | workflow-issue-mr-driven |
|------|---------------------|--------------------------|
| 対象 | `.claude/` 配下のアセット以外。または `.claude/` 配下でも SKILL.md・ルール・テンプレートの typo・文言修正など振る舞いが変わらないもの | `.claude/` 配下のアセット（スキル・フック・ルール・エージェント・settings.json）の作成・変更（新規作成、フックのロジック変更、スキルの手順変更など振る舞いが変わるもの） |

**CLAUDE.md「作業の振り分け」への追加箇条書き**（既存の箇条書きの末尾、`- 仕様: ...` の直前に追加）:

> - `.claude/` 配下のアセット（スキル・フック・ルール・エージェント・settings.json）の作成・変更は `workflow-issue-mr-driven`（`ai-asset-design` → `ai-asset-implementation`）で進める。例外: SKILL.md・ルール・テンプレートの typo・文言修正など振る舞いが変わらないものは `workflow-quick-request` でよい

## 変更対象ファイル

| ファイル / パス | 変更内容 |
|----------------|---------|
| `CLAUDE.md` | 「作業の振り分け」の箇条書きに 1 行追加 |
| `.claude/skills/workflow-quick-request/SKILL.md` | 手順 0 の判定表に「対象」の行を追加 |
| `.claude/skills/workflow-quick-request/evals/evals.json` | フック等 `.claude/` 配下アセットの新規作成依頼を issue-pr 側に振り分けるケース（id: 6）を追加 |

**allowed_paths 案**（実装チケット用）: 標準の `ai-asset-implementation`（`.claude/hooks/**`, `.claude/rules/**`, `.claude/skills/**`, `.claude/settings.json`）に加え、チケット frontmatter へ `allowed_paths: ["CLAUDE.md"]` を追加する（CLAUDE.md は標準の allow_paths に含まれないため）。

## 実装ステップ

1. `CLAUDE.md`「作業の振り分け」に上記の箇条書きを追加する
2. `.claude/skills/workflow-quick-request/SKILL.md` 手順 0 の判定表に「対象」の行を追加する
3. `.claude/skills/workflow-quick-request/evals/evals.json` に id:6 のケースを追加する
4. `evals.json` が妥当な JSON としてパースできることを確認する（`python3 -m json.tool`）
5. SKILL.md と `10_spec/軽作業ワークフロー.md` の判定表の行の文言が一致していることを目視確認する

## 検証方法

- `python3 -m json.tool .claude/skills/workflow-quick-request/evals/evals.json` がエラーなく通ること
- `grep -A2 "^| 対象 |"` で SKILL.md と `10_spec/軽作業ワークフロー.md` の行を突き合わせ、文言が一致していること
- CLAUDE.md の変更後も Markdown のリスト構造が崩れていないこと（目視）

## リスク・未解決事項

- CLAUDE.md は `ai-asset-implementation` の標準 `allow_paths` に含まれないため、実装チケットの `allowed_paths` で個別に許可する（issue #4 の追加情報に明記された対処）
- 入口ガード仕様書（`ワークフロー振り分け実施済み判定.md`）は判断基準を持たないため変更不要。この結論を実装チケットの作業ログ・結果報告に明記し、issue #4 の受け入れ条件「入口ガード仕様書の判断基準に関する記述が CLAUDE.md と一致している」に対する対応（＝該当記述が無いことの確認）として残す
