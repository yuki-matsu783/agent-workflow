## 2. `wf_validate_mv` の拡張方針（003で実施）

`.claude/hooks/workflow-guard.sh` 144-157行目の `wf_validate_mv()` は現在 `wip/10_tickets/*` 以外を一律拒否する。以下のように、`ai-asset-implementation` type に限り `.claude/skills/**` の移動も許可するよう分岐を追加する。

```bash
wf_validate_mv() {
    local tok
    for tok in "$@"; do
        case "${tok}" in
            -*) continue ;;
            QUOTED) return 1 ;;
        esac
        case "${tok//\\//}" in
            wip/10_tickets/*) continue ;;
            .claude/skills/*)
                [ "${TICKET_TYPE}" = "ai-asset-implementation" ] && continue
                return 1
                ;;
            *) return 1 ;;
        esac
    done
    return 0
}
```

`TICKET_TYPE` は `workflow-lib.sh` の `wf_init` 実行後にグローバルへセットされる既存変数（doing チケットの frontmatter から読まれる）なので、追加の状態管理は不要。Edit/Write 側のパス許可（`wf_resolve`）は type の `allow_paths` に `.claude/skills/**` が既に含まれているため変更不要。
