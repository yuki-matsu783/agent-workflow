## 改善提案

- **`gh` CLI 不在環境への対応（振る舞いが変わる）**: `work-boundary.sh` / `merge-prep.sh` は `gh pr comment` / `gh pr view` / `gh issue comment` / `gh pr ready` を直接呼んでおり、GitHub 操作が MCP ツール経由に限定される環境（本セッション）では非local実行ができない。`--local` + 手動 MCP コメント投稿で代替できたが、証跡（`request.comment_id`/`request.url`）が空のまま記録される点は仕様の想定と異なる。恒久対応としては、フックが `gh` の有無を検出してフォールバックする、または `--local` の証跡欄に手動投稿した URL を記録できるオプションを設ける、といった改修が考えられる
- **`wip/` 後片付け漏れの再発防止（軽微〜振る舞いが変わる、要検討）**: 今回のブロックの根本原因は、直前のワークフロー（issue #37/#38）が `merge-prep.sh reset-wip` を実行せずに main へマージされたこと。`merge-prep.sh ready` の前提条件は `reset-wip` 済みであることを検証するが、`ready` を経ずに（例えば手動マージで）PR がクローズされた場合はこの検証を経由しない。完了処理の外で reset-wip 漏れを検知する手段（例: CI での `wip/10_tickets/20_done/` 非空チェック）を検討する価値がある

上記2件はどちらも「振る舞いが変わる」区分（フックのロジック変更）に該当するため、このセッション内では続けて修正せず、`AskUserQuestion` でユーザーに合意を確認した。

**合意結果**:

- `gh` CLI 不在環境への対応 → **新規 issue を作って `workflow-issue-mr-driven` で進める**（本 PR の完了処理の後、続けて着手する）
- `wip/` 後片付け漏れの再発防止 → **今回は見送り**（残課題として記録のみ）
